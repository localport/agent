# Agent error codes

A failure the agent reports to you is a message, the local detail you act on
(a path, a value, the command to run), and its code, such as `[AG021]`. A
failure caused by another shows both codes, innermost first. A refusal from
the control plane or the edge shows the service's message and code (such as
`[SE031]`) exactly as received; those codes are not listed here. Flag usage
errors carry no code. Include every code when you contact support.

Commands leave out causes from the network, the service or agent internals
(endpoint paths, HTTP status, TLS and connection errors) and say so; run the
command again with the global flag `--verbose` (`localport --verbose
<command>`) to print the full cause. A local cause you act on, such as a
file path with its permission error, a port already in use or a config or flag
value the agent refused, is always shown. Several failures at once print one per
line. The agent that runs tunnels and devices (`run`, `up`, the tunnel
form) prints full causes in its log.

Codes up to AG134 are grouped by area: AG001 to AG010 credentials and keys,
AG011 to AG014 file and binary checks, AG020 to AG030 local config, AG031 to
AG039 commands, AG041 to AG045 the device service, AG053 to AG055 terminal
sessions, AG061 to AG063 recordings, AG071 to AG079 network, AG081 to AG093 the
Windows installer, AG101 to AG109 SSH clients, AG110 to AG120 commands
(enrolment, settings, credentials), AG121 to AG125 `localport access`, AG126 to
AG134 control plane calls and credentials. Codes from AG135 on have no area
grouping. The Windows installer and uninstaller exit with the number of their code
(`AG084` exits 84). Three refusals of the installer itself use the Windows
Installer codes instead: exit 1603, a step could not run or take its lock; exit
1618, another Localport installer or uninstaller is running (wait for it to
finish, then run it again); exit 1633, the machine is not running 64-bit
Windows.

| Code | Title | What to do |
|---|---|---|
| AG001 | Renewed device certificate lost | The device's credential store lost the certificate it last registered with. Create a new join command in the dashboard and run it on this machine. |
| AG002 | Device credential used to reach devices | A device credential only registers its device. Use `localport login` or `localport setup <TOKEN>` for a credential that reaches devices. |
| AG003 | No session key set | The control plane answered without the device's session CA keys. Retry later; if it persists, contact support. |
| AG004 | Session keys unreadable | `ticket_keys.json` (the device's session CA keys) beside the device's credential is unreadable or not owner-only. Make it a regular file owned by the account running the agent, mode 0600. |
| AG005 | Session keys busy | Another localport process held the device's key lock. Stop the other process, or retry. |
| AG006 | Renewal in progress | Another localport process is renewing this credential. Wait for it to finish, then retry. |
| AG007 | Credential does not renew | The credential expires instead of renewing: a sign-in, a CI workload credential, or a setup-token credential issued without a renewal time. Run `localport login` again for a sign-in; a CI job requests a new workload credential with a fresh identity token; for a setup-token credential, run `localport setup` with a new setup token once it expires. |
| AG008 | Desktop target keys unreadable | `desktop_pins.json` beside the device's credential is unreadable, not owner-only, or not valid. Make it a regular file owned by the account running the agent, mode 0600, or run `localport set <device> --rdp-reset-pin` (or `--vnc-reset-pin`), which removes the file with every key it held; the next browser connection asks to trust the key again. In an untrusted credential directory the reset fails too: fix the directory's owner and mode first. |
| AG009 | Desktop target keys busy | Another localport process held the device's desktop key lock. Retry. |
| AG010 | Device credential not saved | The control plane issued the device credential, but writing it to the credential store failed; the message names why. The join token is spent: fix the cause, then create a new join command in the dashboard and run it. |
| AG011 | Unsafe service executable | The device service runs only a binary that root (SYSTEM, Administrators or TrustedInstaller on Windows) alone can replace. Install localport with the install script under sudo, or an elevated install.ps1, and run it by that absolute path. |
| AG012 | Untrusted path | A credential file or directory, or a system file of the device service, is a link, has the wrong owner, or is too open. Fix the path the message names. Credential paths on Linux and macOS: owned by the account running the agent, mode 0700 for directories and 0600 for files. Credential paths on Windows: owned by that account, SYSTEM or Administrators; a file grants access to no one else, and a directory grants write access to no one else. Under the machine-wide config directory the device service's account `NT SERVICE\localport-device` is allowed too. System files (the device config directory and the files in it) on Linux and macOS: regular files and a real directory owned by root; the directory writable by no one else (root and the agent group, `localport` or `_localport` on macOS, 0750), `agent.yaml` writable by no one else and unreadable by other (root and the agent group, 0640 or stricter). On Windows: owned by SYSTEM or Administrators, with access for no one else except `NT SERVICE\localport-device`, which may only read, traverse or lock. |
| AG013 | Package manager executable | A localport installed by winget (its portable zip package) or Scoop cannot run the device service: the package manager replaces and removes that file on its own, without stopping or re-registering the service. Install the device with the Localport installer (`localport-setup-<version>-windows-amd64.exe`, the winget installer package, or an elevated install.ps1, which runs the installer), then run `localport up` or `localport service install` by its absolute path, `"%ProgramFiles%\Localport\localport.exe"`. |
| AG014 | Session app invalid | macOS only. `localport up` and `localport service install` install the session launcher app, `Localport.app`, from the folder that holds the `localport` executable to `/Library/Application Support/Localport`. The app is missing there, holds something other than plain files and folders, or is not signed by Localport. Install or upgrade with the install script under sudo, which places both, or extract the release's `localport-session-darwin-<arch>.tar.gz` next to `localport` as the install guide shows, then run the command again. The installed app is left as it was. |
| AG020 | Files with run_as_agent | Without a files root, files serves the whole file system as the session's account; on a device with `run_as_agent: true` that is the agent account, so a files root is required. Set the folder files may reach with `localport set <device> --files-root DIR`, or drop files from `--enable`. |
| AG021 | Devices already running | Another localport process (the device service, `localport run` or `up --foreground`) serves these devices. Stop it, or let it serve them. When it is the device service, the message gives the command that stops it: `sudo systemctl stop localport-device.service` (systemd), `sudo launchctl bootout system/io.localport.device` (macOS), `sudo rc-service localport-device stop` (OpenRC), `sudo /etc/init.d/localport-device stop` (OpenWrt) or `sc.exe stop localport-device` from an elevated prompt (Windows). |
| AG022 | Sessions need the device service | On Windows the session launcher serves only the device service's account, so terminal and files sessions run only under the installed device service. Install it with `localport service install` from an elevated prompt instead of serving the device from this process. |
| AG023 | Terminal, files or forwarding with a host | Terminal, files and forwarding act on the machine running the agent. Remove the host, or remove terminal, files and forwarding. |
| AG024 | Logins without terminal or files | Logins apply only to terminal and files. Enable one of them, or remove the logins. |
| AG025 | Terminal or files without logins | Name at least one login with `--logins`. |
| AG026 | Desktop without target | Give desktop a target with `--rdp` or `--vnc`. |
| AG027 | Files root missing | The files root must be an existing directory the agent can inspect; the message names the path and the reason. Mount or create it, or change it with `localport set`. |
| AG028 | Invalid local config | The local config failed validation; the message names the field. Every command that reads it refuses the same way, `localport set` included, so correct `agent.yaml` by hand: in `$LOCALPORT_HOME` (or `~/.localport`), or as root in the machine-wide config directory. |
| AG029 | Logins with run_as_agent | A device with `run_as_agent: true` runs terminal and files sessions as the agent account (`localport`, `_localport` on macOS), so it lists no logins. Remove `--logins`, or on a host with usable logins remove `run_as_agent` from the device in `agent.yaml` (it has no command-line flag). |
| AG030 | Forwarding without terminal | SSH port forwarding rides an `ssh` connection, so it needs terminal on the same device. Enable both, for example `--enable terminal,forwarding`. |
| AG031 | No enrolled device | The machine-wide config lists no device. Enrol one with `sudo localport up <join-token>` (on Windows, `localport up <join-token>` from an elevated prompt). |
| AG032 | No device can start | Every enrolled device is paused, removed, or has a missing or unreadable credential; the lines above name each one. Resume a paused device with `sudo localport up` (on Windows, `localport up` from an elevated prompt). A removed device, or one whose credential is gone, needs a new join command from the dashboard: run it. |
| AG033 | Device service installed | Deleting the devices is refused while the device service is installed, as when another command installed it during the purge. Run `sudo localport service uninstall --purge` again once that command has finished. |
| AG034 | Flags conflict with stored settings | The flags of a repeated `up <join-token>` differ from the device's settings. Change the settings with `localport set`, or run `up` without the conflicting flags. |
| AG035 | Unexpected argument | `up` takes one join token, and `up` and `down` without one take one device name. Put every flag before that argument or right after it. |
| AG036 | No default login | Terminal and files need a login, and the account running the command gives none: root, or on Windows SYSTEM, a service account, an Entra ID account, or a domain account whose sign-in name cannot be read. Name the accounts with `--logins`; an Entra ID account also with `--password-logins` (`--logins you@domain --password-logins you@domain`). |
| AG037 | Agent account step failed | Root runs the device-store part of this command as the agent account (`localport`, `_localport` on macOS), and that part failed. Its own error, printed above this line, says why. |
| AG038 | Agent account step not started | Root could not start localport as the agent account (`localport`, `_localport` on macOS). Check that the account exists (`id localport`, on macOS `id _localport`) and that the localport executable is intact; reinstall localport if either is missing. |
| AG039 | Internal command | `__agent` is the command localport runs itself, as the agent account. Run the command you meant without it. |
| AG041 | Foreign service definition | A service under the device service's name was not written by localport. Remove it as the message says, then retry. |
| AG042 | Device service not installed | Nothing to remove. Install the service with `sudo localport service install`. |
| AG043 | No supported service manager | This machine has no systemd, OpenRC, OpenWrt procd, launchd or Windows service manager. Run the devices with `localport run` under your own supervisor. |
| AG044 | Windows service marked for deletion | Windows keeps a deleted service until every handle to it closes. Close the Services console, Event Viewer and any tool showing the service, or restart Windows, then retry. |
| AG045 | Device credentials not purged | `service uninstall --purge` removed the service, but deleting the device credentials, the recording spool, the empty identity directory or the agent log directory failed; the message names the path. Fix that path's owner or mode, then run `sudo localport service uninstall --purge` again. |
| AG053 | Device sessions locked | Another localport process serves this device's sessions. Stop the other process. |
| AG054 | Logins disabled | The device has `/etc/nologin`, so sessions run only as root. Remove the file once maintenance is over. Hosts with PAM apply this through `pam_nologin` instead. |
| AG055 | Session launcher from another release | The agent and the session launcher service (`localport-session`) come from different localport releases, usually right after an upgrade. Restart the launcher service: `sudo systemctl restart localport-session` (Linux), `sudo launchctl kickstart -k system/io.localport.session` (macOS), or restart the `localport-session` service (Windows). |
| AG061 | Recording spool full | The recording spool reached its size limit, so recordings stop until uploads catch up. Check the device's connection to the edge on TCP 443. |
| AG062 | Disk space low for recordings | The disk holding the recording spool is nearly full. Free disk space. |
| AG063 | Recording unavailable | A recording could not start; the message names the cause. Causes: no recording uploader, a recording key that is not held or does not match the session certificate, a key that cannot seal the recording's key (malformed, or the wrap fails), too little time before the session's deadline, a spool that cannot store the entry, no session mux, or the control plane refusing, not answering or answering the open with segments already stored. A strict session is refused and a best-effort session runs unrecorded. Retry the session; when it persists, act on the named cause. |
| AG071 | No transport | No connection to the edge worked. Check that this machine reaches the edge on TCP 443 and that no firewall or proxy blocks it. |
| AG072 | Registration failed | The connection to the edge broke or carried an unexpected answer while the tunnel or device registered. localport retries on its own; when it persists, contact support with the agent log. |
| AG073 | Redirect to an untrusted host | The edge sent this agent to a host outside the Localport service, so the agent refused to follow. localport retries on its own; contact support. |
| AG074 | Too many redirects | The edge redirected the agent more times than it follows. localport retries on its own; when it persists, contact support. |
| AG075 | Too many inbound connections | More inbound connections were opening at once than the agent serves, so this one was refused. Visitors can retry; when it persists, the local service is too slow to accept connections. |
| AG076 | Data connection failed | The agent could not open a data connection to the edge for an inbound connection. Check that this machine reaches the edge on TCP 443. |
| AG077 | Local service unreachable | The local service did not accept the connection (the message names the address and the cause). Check that the service runs and listens on that address and port. |
| AG078 | Port not allowed | The edge asked for a port the device does not serve: not in its port list or outside its `--allow-ports`. Add the port to the device in the dashboard, or widen `--allow-ports`. |
| AG079 | Connection broke while relaying | An inbound connection ended with an error from the visitor's side or the local service (the message names it), not a normal close. Nothing to do for a single connection; when many break, check the local service and the network. |
| AG081 | Installer step not elevated | A Windows installer step (`localport system`) ran without elevation. Run the Localport installer as an Administrator; it asks for elevation itself. |
| AG082 | Install directory unsafe | The install directory, or a directory above it, is owned by someone other than SYSTEM or Administrators, or grants another account a right that replaces an entry, or on the install directory itself one that adds a file or folder. Choose a directory under `%ProgramFiles%`, or fix the owner and permissions the message names. |
| AG083 | Device services did not stop | The installer could not stop the device or session launcher service in time, so it undid the install: the previous files, settings and services are as they were. Stop the services (`sc.exe stop localport-device`, `sc.exe stop localport-session`), then run the installer again. |
| AG084 | Install not committed | A product file could not be put in place (the message names it and the cause, often a file another program holds open), so the installer undid the install: the previous files, settings and services are as they were. Close that program, then run the installer again. |
| AG085 | Device services not re-registered | Registering the device services for the new executables failed, so the installer undid the install: the previous files, settings and services are as they were. The message names the cause; fix it, then run the installer again. |
| AG086 | Foreign service in the install directory | A service localport did not create runs a program inside the install directory, so uninstalling would break it; nothing was changed. Remove or move that service (the message names it), then uninstall again. |
| AG087 | Machine PATH not updated | The installer could not add its directory to the machine `Path`, so it undid the install: the previous files, settings and services are as they were. The message names the cause; fix it, then run the installer again. |
| AG088 | Installer step invalid | The installer called a `localport system` step that this `localport.exe` does not know, or with the wrong arguments; the installer and its executable come from different releases. Nothing was changed. Download the installer again from the releases page and run it. |
| AG089 | Uninstall not prepared | A step of the uninstall failed (listing or removing the device services, the `Path` entry, the Add/Remove Programs entry or a file), so the uninstaller undid it: the install is as it was. The message names the cause; fix it (for example, close a tool that holds a service open, or restart Windows), then uninstall again. |
| AG090 | Install rollback failed | An install or uninstall failed and undoing it also failed, so the machine may be between two states. The journal under `<install directory>\.localport-txn\` is kept, and the next run of the installer or uninstaller finishes the undo before it does anything else. Run the installer again; the message names the step that could not be undone. The undo also reports AG090 when it finished but removed a device service instead of restoring it, because the program that service ran was deleted or can be replaced by another account: run `localport service install` as an Administrator to register the service again. |
| AG091 | Service configuration busy | Another installer, uninstaller, `localport up` or `localport service` command is changing the device services and did not finish within 2 minutes; or an install or uninstall that was interrupted is still open in an install directory, which the message names (its undo would reverse this change); or the lock could not be taken (the message names the cause). Wait for the other command to finish and run the command again. For an interrupted install or uninstall, run the Localport installer, or the uninstaller, for the directory the message names: it undoes the interrupted one first. Running an installer for a different directory refuses again. |
| AG092 | Uninstall entry not written | The installer could not write its Add/Remove Programs entry, so it undid the install: the previous files, settings and services are as they were. The message names the cause; fix it, then run the installer again. |
| AG093 | Device state not purged | The uninstall finished and the uninstaller removed itself, but removing the device identities and config it was asked to purge failed, so they stay under `%ProgramData%\localport-device`. The message names the cause; fix it, then delete that directory as an Administrator. The device certificates stay valid until the devices are removed in the dashboard. |
| AG101 | No session certificate | `ssh-proxy` found no session certificate, edge URL or client key for this credential, login and device; `ssh-cert`, which the `Match exec` line of the `ssh-config` block runs, writes them. Run the `localport ssh-cert` command the message names, or connect with `localport ssh`. |
| AG102 | SSH client files busy | Another `localport ssh-cert` held the lock on this credential's client files for 30 seconds, longer than a certificate mint takes. Retry; when it persists, end the stuck `localport ssh-cert` process. |
| AG103 | Login refused for SSH | The login holds a shell character (`' ` " ; & < > \| ( ) { } $`), starts with `-`, holds `\`, `*` or `?` on Windows, or holds `\\` or ends in `\` elsewhere, so it cannot travel through ssh_config's commands. Name a Windows domain account in its UPN form, `alice@corp.example`. |
| AG104 | Path unusable in ssh_config | The localport path or the state root holds a quote, `$`, `` ` ``, a line break or, outside Windows, `\`. Move localport or `LOCALPORT_HOME` to a path without them. |
| AG105 | SSH client files unusable | The client key, certificate, URL, known_hosts file or their directory under `<state root>/ssh/` cannot be read or written; the message names the file. Fix its owner or mode, or remove it so the next `localport ssh-cert` writes it again. |
| AG106 | Session certificate answer refused | The control plane answered with a certificate for another key or login, an expired one, or no usable host key or URL. Check this machine's clock; when it persists, contact support. |
| AG107 | Session certificate not issued | The control plane refused or did not answer the mint; its own code follows when it refused. Check the login and your access to the device, or run with `--verbose` for the cause. |
| AG108 | Session connection failed | The connection to the device's edge broke or could not open. Check this machine's network; run with `--verbose` for the cause. |
| AG109 | Session ended | The edge ended the session; the reason it gave follows the message. Connect again; when the reason persists, contact support with it. |
| AG110 | Device enrolled, config not written | The join token is spent and the device holds its credential, but `agent.yaml` was not written; the message names the cause and what to run. Fix the cause, then create a new join command in the dashboard. |
| AG111 | Credential expired | The credential's certificate expired and an expired certificate cannot be renewed. Sign in again with `localport login`, or run `localport setup` with a new setup token for a setup-token credential. |
| AG112 | localport path unknown | The operating system did not report where this localport executable is. Run localport by its full path. |
| AG113 | Current user unknown | The account running the command cannot be looked up, so no default login exists. Name the login (`login@host`, or `--logins`). For `up` or `set` with `--logins` without root or an elevated shell, the account also could not be read (on Windows: SYSTEM, a service account, Entra ID, or a domain account whose sign-in name is unavailable): run the command with sudo or from an elevated shell. |
| AG114 | OpenSSH client unavailable | `ssh` is not installed, not on `PATH`, or could not start. Install the OpenSSH client. |
| AG115 | Credential not saved | The credential was issued but could not be saved; the message says what to run again. Fix the credential directory's owner or mode first. |
| AG116 | Settings saved but not applied | `set`, `up` or `down` saved the settings, but the run serving the devices did not apply them: reloading or starting the device service failed, or a foreground run (`localport run`, `up --foreground`) did not answer its control endpoint. A foreground run that is still starting answers that it applies the settings when it starts; that is not this error. Apply them with the command the message names. When the message says the control endpoint is not a foreground run's, the socket (`/run/localport/control.sock`, `/var/run/localport/control.sock` on macOS) or pipe is not owned by root (SYSTEM or Administrators on Windows) or is open to others: find what created it and remove it. |
| AG117 | Desktop key not forgotten | `set --rdp-reset-pin` or `--vnc-reset-pin` could not change `desktop_pins.json`; its own code follows. Retry; fix the file's owner or mode if it persists. |
| AG118 | Device name ambiguous | The name matches more than one enrolled device. Use the full identity from the local config. |
| AG119 | Device enrolled, service not installed | The device is enrolled and its credential saved, but installing its service failed. Fix the cause the message names, then run the `localport service install` command it shows; no new join token is needed. |
| AG120 | Device not found | The name matches no device in the local config. Check the spelling, or use the full identity the local config lists. |
| AG121 | Client certificate unusable | The client certificate or key from `--pem`, `--p12`, the access config or the store cannot be read, parsed or used, or is not yet valid or expired. Check the file and this machine's clock, or obtain a new credential. |
| AG122 | Invalid access config | The access config file cannot be read or holds an invalid entry; the message names the file and the entry. Fix the entry. |
| AG123 | Local forward not opened | A `-L` local address or socket could not listen: in use, or a path that is not a socket. Choose another address, or stop the process holding it. |
| AG124 | Device refused the connection | The device or its edge refused this certificate, identity or port; the message says which and what to do. |
| AG125 | Device unreachable | The device is offline, its address is unknown, or it does not answer as a Localport edge. Check the address and that the device is connected. |
| AG126 | Control plane unreachable | A call to the control plane got no complete answer: DNS, connection, TLS, timeout, or the answer broke off. Check the network and the `--api` address; `--verbose` prints the cause. Calls that create state or spend a token are retried under the same idempotency key, so a retry never spends a token twice. |
| AG127 | Control plane answer unusable | The control plane answered with something the agent cannot use; the message says what. Run the command again; if it repeats, contact support with the code. |
| AG128 | No credential | This machine holds no credential. Run `localport login`, or `localport setup <TOKEN>` with a setup token. |
| AG129 | No matching credential | No stored credential matches the selection; the message lists those on this machine. Pick one of them with `--identity`. |
| AG130 | Several credentials match | The selection matches more than one stored credential; the message lists them. Narrow it with `--identity`. |
| AG131 | Credential unreadable | A stored credential (metadata, key or certificate, or a renewed one awaiting use) cannot be read or does not fit together; the message names it. Fix the file the message names, or remove the credential and obtain a new one. |
| AG132 | Credential store unusable | The credential directory cannot be created, read or changed, or there is no home directory to hold it. Fix the path the message names, or set `LOCALPORT_HOME`. |
| AG133 | CI token unavailable | The CI platform's OIDC token could not be obtained: no workload identity in the environment, or the platform's token service refused or could not be reached. On GitHub Actions add `permissions: { id-token: write }` to the job, or set `LOCALPORT_OIDC_TOKEN`. |
| AG134 | Sign-in expired | The sign-in was not approved before it expired, or the control plane could not be reached while waiting. Run `localport login` again. |
| AG135 | Service manager failed | A service manager command or call (systemctl, rc-service, ubus, launchctl, or the Windows service control manager) failed; the message names the step. `--verbose` prints the tool's output. Check the service manager's own log, then run the command again. |
| AG136 | Service definition not written | The device service definition file or its directory could not be read, written or removed; the message names the path. Fix the path's permissions or free space. |
| AG137 | Agent account missing | The agent account (`localport`, `_localport` on macOS) does not exist. Run `sudo localport service install`, which creates it. On macOS a recreated account takes the user id that owns the device's `identity` directory whenever that id lies in 450-499 and no other account holds it, so the stored credentials stay usable. Its group is the existing `_localport` group, or a new one whose id is the first of the directory's group id, that user id, or a fresh id that lies in 450-499 and no group holds. When the directory's owner does not qualify, the account takes fresh ids: an empty directory owned by root is then given to the account, and any other directory is refused with `AG012`; move it aside and enrol again. |
| AG138 | Agent account not changed | The agent account or group (`localport`, `_localport` on macOS) could not be created, looked up or inspected; the message names the step. On a host without useradd or adduser, install the localport package, which creates the account. |
| AG139 | Needs root | Only root, or an elevated Administrator on Windows, changes the device config directory. Run the command with sudo, or from an elevated prompt. |
| AG140 | Agent group missing | The agent group (`localport`, `_localport` on macOS) does not exist. Run `sudo localport service install`, which creates it. |
| AG141 | Local config unusable | The local config (`agent.yaml`), its directory or its lock file cannot be located, read, secured or locked; the message names the path. Fix the path, or set `LOCALPORT_HOME` when there is no home directory. |
| AG142 | Local config busy | Another localport command is changing the local config. Wait for it to finish, then run the command again. |
| AG143 | Local config not written | The local config file could not be written; the message names it. Fix the directory's permissions or free space. |
| AG144 | Invalid tunnel config | The tunnel config file given with `--config` cannot be read, or holds an invalid entry or an unset `${VAR}`; the message names the file and the entry. Fix the entry. |
| AG145 | Log file unusable | `run --log-file` could not open its path as the agent's log: a link, a directory, or no permission. Fix the path; the service manager's own log holds this message. |
| AG146 | Token file unreadable | The file a `*_FILE` variable names (such as `LOCALPORT_TOKEN_FILE`) cannot be read, or is a link, not owned by this account or readable by others. Fix the file: owned by this account, mode 0600. |
| AG147 | Agent account unsafe | Linux: the existing `localport` account is not in the shape `useradd --system`, systemd-sysusers and the packages create, and localport does not edit it to fit. The message names each problem: a password that can unlock it (a crypt hash, or none, in `/etc/shadow`), a shell other than `nologin` or `false`, a primary group other than `localport`, user id 0, a user id above `SYS_UID_MAX` of `/etc/login.defs` (999 when unset; not checked on a host without that file, such as OpenWrt), a home directory it owns or that group or others may write, or membership in `root`, `wheel`, `sudo`, `admin`, `adm`, `shadow`, `disk`, `docker` or `lxd`. Remove it with `sudo userdel localport` (and `sudo groupdel localport` when the group is named), then run `sudo localport service install`, which recreates it. macOS: the existing `_localport` account is not in the shape localport creates, and localport does not edit it to fit. The message names each problem: an `AuthenticationAuthority` or a password other than `*` (it could log in), a shell other than `/usr/bin/false`, a primary group other than `_localport`, a user id outside 450-499, or membership in `admin`, `wheel` or `staff` (staff reaches every user's home directory). Remove the account with `sudo dscl . -delete /Users/_localport`, then run `sudo localport service install`, which recreates it. Deleting the account does not remove its name from other groups: for a named membership, also run `sudo dseditgroup -o edit -d _localport -t user <group>`. When the primary group is named and a `_localport` group exists, delete that group too with `sudo dscl . -delete /Groups/_localport`, since a recreated account joins it. |
| AG148 | Unknown command | The first word is neither a localport command nor a tunnel protocol (`http`, `https`, `tcp`, `tls`). `localport help` lists the commands; a device enrols with `localport up <join-token>`. |
| AG149 | Credential store busy | `localport service uninstall --purge` holds the credential store while it deletes the device credentials. Retry when it finishes. |
| AG150 | Device not named | Several devices are enrolled and `up` or `down` was run without a name outside a terminal. The message lists the command for each device; name one, or give `--all`. |
| AG151 | No device chosen | `up` or `down` asked which device to act on and the input ended before a choice. Nothing changed. |
| AG152 | Agent account step output refused | Root runs the store steps of `up`, `down` and `set` as the agent account (`localport`, `_localport` on macOS) and refused what one returned: too large, or not in the format this version writes. Retry; if it persists, reinstall localport. Listing the devices changes nothing. After an enrolment the join token is spent: create a new join token for the device in the dashboard. |
| AG153 | Not a join token | `up` was given enrolment flags (such as `--foreground` or `--enable`) and an argument that is not a join token (`lpj_...`). Enrolment flags apply only with the join token the dashboard shows. To resume a paused device, run `sudo localport up <device>` with no other flag. Nothing was sent to the control plane. |
| AG154 | Device limit reached | One machine runs at most 64 devices, and its config lists 64. `up <join-token>` refuses before it spends the token, also for a device already enrolled. Remove a device from this machine in the dashboard, then run `up` again. |
| AG155 | Join token with --config | `up --config` runs the tunnels of a config file and enrols nothing, so it takes no join token. Run `up <join-token>` and `up --config <file>` separately. |
| AG156 | Join token required | `up` was given enrolment flags without a join token. Create the device in the dashboard and run the command it shows. |
| AG157 | --no-mux not available as root | A device enrolled as root runs as the agent account, under the device service or, with `--foreground`, as `localport run --system`; both keep the multiplexed connection that browser and CLI sessions need. Run the device as an ordinary user with `--no-mux`, or leave the flag out. |
| AG158 | No credential chosen | A command asked which stored credential to use and the input ended before a choice. Nothing changed. Choose one with `--identity`. |
| AG159 | System run needs root | `localport run --system` serves this machine's devices in the foreground, and `up`, `down` and `set` reach such a run only when root (an elevated Administrator on Windows) runs it. Run `sudo localport run`, or on Windows `localport run` in an elevated shell. The device service runs the devices under its own account. |
| AG160 | Control endpoint unavailable | A foreground run (`localport run`, `up --foreground`) could not serve the control endpoint that `up`, `down` and `set` use to apply settings, so it did not start. When the message says the endpoint is not a foreground run's, the directory (`/run/localport`, `/var/run/localport` on macOS) or the socket at `control.sock` is not root's or is open to others: find what created it, remove it, and start the run again. Otherwise start the run again, and if it fails again contact support with the output of `localport --verbose run`. |
| AG161 | Service install busy | Another `localport service install` or `uninstall` is installing or removing Localport.app on macOS. Wait for it to finish, then run the command again. |
| AG162 | Unexpected error | The command failed for a reason it has no message for. Run it again with `--verbose` to see the cause, and contact support with that output if it fails again. |
